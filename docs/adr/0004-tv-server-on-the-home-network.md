# The TV Server listens on the home network behind a click-to-approve IP allowlist, not localhost-only with no auth

The TV app reaches the library through the **TV Server**: a second `Bun.serve` in the same process on port **4401** (`TUVA_TV_PORT` overrides it, for tests only), bound to all IPv4 interfaces, started by a button in the browser app and off at every launch, while the localhost app on 127.0.0.1:4400 stays exactly as it is. This supersedes the spec's "`localhost` only, no auth" rule for the TV Server alone. Every request is checked against the source IP: an unknown IP gets a 403 (the TV shows "Approve this TV on the Mac") and raises "Allow TV at ‹IP›? Allow / Deny" in the browser's top bar; Allow adds an **Approved TV** to an allowlist kept in the database across launches (a DHCP change costs one more click), Deny silences that IP until the TV Server is next turned on. The alternatives were typing the TV's IP by hand, a pairing code typed in the browser, and a per-device token alongside the IP (guards only against another device inheriting the TV's address on a single-user home network, and adds state to the shell). The TV Server serves a fixed route list reusing the localhost handlers, and anything not on it is a 404: `GET /api/health` to anyone (identifies "TuvaVideos TV Server" only, so the TV app can find the Mac by trying its last address, then sweeping the /24 on 4401, then asking for the address on the remote); to Approved TVs, the reads `/api/videos`, `/api/videos/:id` and its `chapters` and `audio`, `/api/audio-presets`, `/api/artists`, `/api/songs`, `/api/songs/:uuid`, `/api/favorites`, `/api/search`, `/api/copies/:id` and its `keyframes`, `/copy/:id`, `/thumbs/:id/{poster,strip}.webp`, the only writes Resume position and view, and two TV-only surfaces, the TV app's UI files and the Live remux streams. Studio, Rescan, Roots, every edit, merge and delete, screenshot, loop, reveal, choose-file, `/copy/:id/pcm` and quit are never exposed; Favorites are browsed, not starred. The installed TV app is a thin signed shell that finds the server and loads its UI from the TV Server, so UI updates ship with the Mac code and only the shell needs the Samsung certificate. The TV plays each Video with its saved Audio settings through the browser's audio code, and an Audio preset can be picked on the TV for the current play only, never saved; if the R85H will not route `<video>` sound through Web Audio, the TV plays it untouched. The top bar shows "TV" (off), "TV on · ‹Mac IP›:4401", the approval prompt, or "TV · ‹model› · playing ‹title›" while an Approved TV has made a request in the last 60 s; its menu holds Turn off and the Approved TVs with Remove. Turning the TV Server off is a hard stop: the listener closes, open streams and any Live remux are cut, the TV shows "TV Server turned off" over the paused frame, and the last saved Resume position stands. Consequence: the app now accepts connections from the network, so macOS's firewall (on here) asks once, and again after each Bun upgrade, whether `bun` may accept incoming connections; the route list is the security boundary and must be extended deliberately; a TV prototype must still confirm that remote keys and `<video>` work in a remotely loaded page and that Web Audio processing works on the R85H. Decided in [issue #49](https://github.com/IncoherentThoughts/TuvaVideos/issues/49).
